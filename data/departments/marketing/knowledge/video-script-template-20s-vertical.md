# 20-Second Vertical Video Script Template

**Format**: 9:16 vertical (1080x1920)
**Platform**: X/Twitter, Instagram Reels, TikTok
**Target Audience**: Technical developers
**Tone**: Calm, confident, technical (not salesy)

---

## Structure

### Timing Breakdown
- **0-3s**: Hook (problem awareness or surprising fact)
- **4-7s**: Problem amplification (make the pain clear)
- **8-13s**: Solution introduction (brand + product reveal)
- **14-17s**: Key differentiator (unique value prop)
- **18-20s**: Call-to-action (brand reinforcement, no hard sell)

**Total**: Exactly 20 seconds

---

## Voice-over Guidelines

### Tone
- **Calm and authoritative**: Like explaining architecture to a peer
- **NOT overly enthusiastic**: Avoid hype, exclamation marks in speech
- **Conversational pacing**: Natural speaking rhythm, slight pauses between sections
- **Technical credibility**: Use proper terminology, don't dumb it down

### Delivery
- **Total duration**: 20 seconds (script should time out exactly)
- **Pacing test**: Read the script aloud at normal conversation speed
- **Emphasis**: Slightly emphasize brand name, product tagline, and final CTA
- **No filler words**: Cut "um", "you know", "basically", etc.

### Voice Profile (for AI voice synthesis)
- **Gender**: Male or neutral (avoid overly gendered voices)
- **Age**: 30-45 equivalent (mature, experienced)
- **Accent**: Neutral American or British English
- **Reference voices**: Tech podcast hosts, conference speakers, senior engineers explaining their work

---

## On-Screen Text Guidelines

### Typography
- **Font**: Inter or Poppins (sans-serif)
- **Size**: Large enough for mobile (test at 375px width)
- **Color**: White (#ffffff) or cyan (#00d9ff)
- **Background**: Dark (black or deep blue), never white
- **Position**: Center or lower-third (avoid top 10% due to profile pictures on social)

### Animation
- **Fade in**: 0.3s ease-in
- **Hold**: Match voice-over timing
- **Fade out**: 0.3s ease-out
- **No distracting motion**: Text should be readable, not bouncing/spinning

### Content Rules
- **2-4 words per text element**: Short and punchy
- **Match spoken words**: Text should echo voice-over, not introduce new concepts
- **Brand name in ALL CAPS**: "MYELIN" not "Myelin" for logo reveal moment
- **Social handle at end**: Include @ handle in final 2 seconds

## Visual Guidelines

### Shot Types
1. **Opening (0-3s)**: Close-up or medium shot, cinematic
2. **Problem (4-7s)**: Over-shoulder, detail shot, or frustration POV
3. **Solution (8-13s)**: Logo animation, product interface, code snippet
4. **Differentiator (14-17s)**: Diagram, technical illustration, or feature demo
5. **Closing (18-20s)**: Wide or medium shot, success state

### Visual Consistency
- **Color palette**: Stick to brand colors (dark blue, cyan, black, white)
- **Lighting**: Blue or cyan accent lighting in photos/video
- **Depth**: Use shallow depth of field for cinematic feel
- **Motion**: Subtle animations, no jarring transitions

### Platform Optimization
- **Vertical format**: 9:16 aspect ratio (1080x1920 minimum)
- **Safe zones**: Keep critical content within center 80% of frame
- **Autoplay assumption**: Design for muted viewing (text must carry message)
- **File size**: <50MB for Twitter, <30MB for Instagram

## Common Patterns for Developer Products

### Hook Patterns (0-3s)
- **Present tense declaration**: "AI models are getting bigger."
- **Surprising stat**: "90% of developers struggle with X."
- **Bold claim**: "You don't need a data science degree."
- **Relatable frustration**: "Debugging production issues at 3 AM."

### Problem Patterns (4-7s)
- **Time cost**: "Building X takes 6 months."
- **Expertise barrier**: "Requires a PhD in Y."
- **Tool complexity**: "30 lines of boilerplate for Z."
- **Frustration moment**: Show developer overwhelmed/confused

### Solution Patterns (8-13s)
- **Brand + tagline**: "ProductName: Tagline explaining what it does"
- **API call example**: Show clean, simple code that solves the problem
- **Before/after**: Messy solution → clean solution
- **Logo reveal**: Animated entrance with brand colors

### Differentiator Patterns (14-17s)
- **Technical diagram**: Show architecture, data flow, or system design
- **Performance metric**: "10x faster", "90% less code", specific numbers
- **Security/privacy**: Show encryption, zero-knowledge proofs, compliance
- **Developer experience**: Clean API, great docs, fast onboarding

### CTA Patterns (18-20s)
- **Aspirational**: "Build the future.", "Ship faster.", "Deploy with confidence."
- **No hard ask**: Don't say "Sign up now!" — too salesy for devs
- **Brand reinforcement**: Show confident user or successful outcome
- **Social proof**: Include @ handle, not "Click link in bio"

## Production Checklist

### Pre-Production
- [ ] Script written and timed (exactly 20 seconds when read aloud)
- [ ] On-screen text drafted (2-4 words per moment)
- [ ] Visual storyboard with 5 key shots identified
- [ ] Voice-over talent or AI voice selected
- [ ] Brand colors and fonts specified

### Production
- [ ] Voice-over recorded (20 seconds, proper pacing)
- [ ] Visuals generated (5 shots at 1080x1920)
- [ ] Logo animation created (fade in + scale, ~1s)
- [ ] Text overlays positioned and timed
- [ ] Color grading applied (consistent brand palette)

### Post-Production
- [ ] Audio mixed (voice-over clear, no background noise)
- [ ] Text animations synced with voice-over
- [ ] Shot transitions smooth (0.3-0.5s cross-dissolves)
- [ ] Exported at 1080x1920, H.264, <50MB
- [ ] Mobile readability tested (view on phone)

### Platform-Specific
- [ ] **Twitter/X**: <512MB, H.264, AAC audio, 2:20 max length
- [ ] **Instagram Reels**: <30MB, 9:16, H.264, 60s max length
- [ ] **TikTok**: <287.6MB, 9:16, H.264, 10min max length

## Adaptation for Different Products

### For Infrastructure/Backend Tools
- **Focus**: Performance, reliability, scalability
- **Visuals**: Terminal commands, architecture diagrams, metrics dashboards
- **Tone**: Even more technical, show code and systems

### For Frontend/UI Tools
- **Focus**: Developer experience, design system, components
- **Visuals**: UI components, code + rendered output side-by-side
- **Tone**: Balance technical with visual beauty

### For APIs/SDKs
- **Focus**: Ease of integration, clean API design, documentation
- **Visuals**: Code snippets, API call → response flow
- **Tone**: Emphasize "3 lines of code" simplicity

### For Security/Privacy Products
- **Focus**: Threat models, compliance, zero-knowledge architecture
- **Visuals**: Encryption flow, threat diagrams, lock/shield iconography
- **Tone**: Serious, credible, avoid fear-mongering

## Metrics & Success Criteria

### Engagement Metrics (X/Twitter)
- **Views**: Baseline metric, aim for 1000+ in first 24h
- **Engagement rate**: (likes + retweets + replies) / views, aim for >5%
- **Click-through**: If profile visits increase, hook worked
- **Replies**: Developers asking "when can I try this?" = success

### Quality Indicators
- **Positive replies**: "This is exactly what I need" comments
- **Technical questions**: Developers asking about architecture, APIs, pricing
- **Shares to peers**: "cc @coworker" or quote tweets to their network
- **Low negative reactions**: Few "looks like vaporware" or "just use X instead" replies

### Red Flags
- **High drop-off**: If 80% stop watching in first 3 seconds, hook failed
- **Confusion**: Replies asking "what does this even do?" = messaging unclear
- **Mockery**: Quote tweets making fun of buzzwords or vague claims = tone wrong

## Examples of 20s Dev Tool Videos (Reference)

### Good Examples (Patterns to Copy)
- **Vercel**: Clean code demos, fast pacing, "Deploy in seconds" messaging
- **Supabase**: Before/after comparisons, "Postgres + Auth + Storage" clarity
- **Fly.io**: Terminal commands, technical architecture, no fluff
- **Railway**: Problem (complex deployments) → solution (simple CLI), developer-first

### Bad Examples (Patterns to Avoid)
- **Generic SaaS**: Stock footage, buzzwords ("revolutionize your workflow"), no code shown
- **Overly slick**: Motion graphics that look expensive but say nothing
- **Feature dump**: "We have X, Y, Z, and W" without explaining why anyone cares
- **Salesy CTAs**: "Sign up now for 50% off!" doesn't work for developer tools

## Iteration & Testing

### Test With Target Audience
1. Show draft to 3-5 developers (not marketers)
2. Ask: "What does this product do?" (without explaining)
3. If they can't answer clearly, messaging failed
4. Iterate on script, not just visuals

### A/B Testing Variables
- **Hook**: Test different opening lines (problem vs. solution vs. stat)
- **Visuals**: Test code-heavy vs. diagram-heavy versions
- **CTA**: Test aspirational vs. specific CTAs
- **Thumbnail**: First frame matters for autoplay scroll-stopping

## Template Usage

When creating a new 20s vertical video:

1. Copy this template
2. Fill in the script timing table with your product's story
3. Draft voice-over script and time it (must be exactly 20s)
4. Sketch visual storyboard (5 key shots)
5. Identify required assets (logos, photos, diagrams, code snippets)
6. Record/generate assets
7. Assemble in video editor (CapCut, Premiere, Final Cut)
8. Export and test on mobile device before posting

**Reference**: See `myelin-brand-visual-identity.md` for brand colors, typography, and visual style guidelines.
