## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`margin-right: 4px` on status dots), inline code padding (`1px 5px`) |
| sm | 8px | Compact element spacing (card-title `padding-bottom`, build log `margin-bottom`, tab-bar gap, log-entry-header gap) |
| md | 16px | Default card padding, card margin-bottom, sidebar padding |
| lg | 24px | Section padding (stat row spacing, page heading margin) |
| xl | 32px | Layout gaps (sidebar width sections, gallery grid container padding) |
| 2xl | 48px | Major section breaks (page-level vertical rhythm) |
| 3xl | 64px | Page-level spacing (sidebar total width: ~200px uses multiples) |

Exceptions (all multiples of 4):
- Chat bubble padding: `8px 16px` (snapped from Doc 12's 10px 14px to nearest grid-safe values)
- Chat input min-height: `48px` (snapped from Doc 12's 44px to nearest multiple of 4)
- Send button padding: `12px 16px` (snapped from Doc 12's 12px 18px to nearest grid-safe values)
- Badge padding: `4px 8px` (snapped from Doc 12's 2px 7px to nearest grid-safe values)
- Button padding: `4px 12px` default, `4px 8px` small (snapped from Doc 12's 5px 12px and 3px 8px)
- Avatar size: `32px` chat / `28px` workspace (snapped from Doc 12's 30px to nearest multiple of 4)

Source: Doc 12 CSS variables and component definitions, adjusted to 4px grid compliance.

## Interaction Contracts

### Tamir Page Flow (TAMIR-01 through TAMIR-08)

1. **Initial state:** Full-width chat, no canvas. Input placeholder: "What would you like to get done?"
2. **CEO sends message:** POST `/api/tamir/route`. Tamir routes immediately (no clarifying question per D-04). Response includes framing sentence + department recommendation.
3. **Routing buttons appear:** "Plan with [Dept Head name]" and "Plan with Tamir" (D-05). CEO picks one.
4. **Multi-turn planning chat:** Messages via POST `/api/tasks/[taskId]/message`. Each response uses `AGENT_TURN_SCHEMA` structured output (D-06). Chat stays full-width.
5. **Plan ready signal:** When agent returns `turn_type === "plan_ready"`, canvas split pane slides in from right (40% chat / 60% canvas) per D-07.
6. **Canvas renders plan:** Typewriter effect at 40-70ms/line via `marked.js` (D-08). Blinking cursor animation during render.
7. **Edit mode:** CEO toggles "Save Plan" / "Edit Plan" button. "Edit Plan" shows raw markdown textarea. "Save Plan" persists via PUT `/api/tasks/[taskId]/artifact`.
8. **Configuration panel:** Below plan on canvas. Autonomy slider (Minimal/Balanced/High/Full), max budget input (USD, default $10), constraints textarea. Saved via PUT `/api/tasks/[taskId]/config`.
9. **Tool/Skill gallery:** VS Code extension card layout. 300ms debounce search. Source toggles (Glama + Composio for tools, ClawHub for skills, Company DB for both). Stars descending sort (D-10). Cross-dept items at 0.5 opacity (D-12). CEO hint text input per selected item.
10. **Approve:** POST `/api/tasks/[taskId]/approve`. Creates execution desk, enqueues task_run, redirects to `/deliverables/[id]`.

### Page rehydration (D-16, D-17)
- On mount, load chat history from JSONL via GET `/api/tasks/[taskId]/chat`.
- If task state is `working` and an artifact exists, render split pane immediately (no typewriter replay).

### Dashboard (UI-03, D-13, D-15)
- Default landing page (`/`).
- Stats row: active agents count, active tasks count, pending approvals count, total deliverables count.
- Agent status panel: colored dot per employee (green = activity < 30s, amber = heartbeat > 30s, gray = idle).
- Recent activity timeline: last 10 rows from `activity_log`, polled on mount, updated via SSE `task:transition` events.

### Deliverables Gallery (UI-04)
- Card grid with title, dept badge, type badge, status, creator, date, preview snippet.
- In-progress tasks at top with amber left border (`border-left: 3px solid var(--amber)`).
- Department filter tabs + search input (300ms debounce).

### Org Context (UI-05)
- Department tabs: Tech / Marketing / Operations.
- Left column: Agent Memory (collapsible cards), Knowledge Library (expandable cards), Tools + Skills gallery.
- Right column: Employee cards with avatar, status, memory preview, past tasks accordion.
- Skill approval UI (UI-08): Approve / Submit to CEO / Dismiss buttons per pending skill.

### Vault (UI-06)
- FTS5 search input with 300ms debounce.
- Document list: title, dept badge, filed_by, date.
- Click to expand: full rendered markdown via `marked.js` with `.md-render` class.

### Agent Profile (UI-07)
- Stub page at `/agents/[id]`.
- Read-only display: card.json data + MEMORY.md rendered + recent task list with deliverable links.

### Hire Approval (UI-09, D-18)
- Inline in build log when `task.state === 'input-required'` AND `metadata.inputType === 'hire_approval'`.
- Approve button calls POST `/api/hire_requests/[id]/approve`.

### SSE Wiring (UI-10)
- Client-side `EventSource` to `/api/sse`.
- Events consumed: `task:transition`, `task:buildlog`, `task:heartbeat`, `task:review`, `hire:requested`, `agent:invoked`.
- Reconnection: simple 3s retry on disconnect (Claude's discretion area).
- Remove listeners on component unmount / stream cancel.
