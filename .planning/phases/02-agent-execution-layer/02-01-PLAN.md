**src/lib/mcp/access-control.ts** -- Per TOOL-02, role-based access control factory:

```typescript
// MCP tools are exposed as mcp__myelin__toolname by the SDK
const TAMIR_ONLY = ['mcp__myelin__read_inbox', 'mcp__myelin__get_dept_status'];
const DEPT_HEAD_ONLY = [
  'mcp__myelin__approve_deliverable',
  'mcp__myelin__request_changes',
  'mcp__myelin__hire_employee',
  'mcp__myelin__file_to_vault',
];
const TEMP_ALLOWED = [
  'mcp__myelin__read_memory',
  'mcp__myelin__write_memory',
  'mcp__myelin__read_knowledge',
  'mcp__myelin__search_knowledge',
  'mcp__myelin__promote_to_deliverable',
  'mcp__myelin__propose_skill',
  'mcp__myelin__submit_for_review',
];

export type CanUseToolFn = (
  toolName: string,
  input: Record<string, unknown>,
  options: { signal: AbortSignal; toolUseID: string; agentID?: string }
) => Promise<{ behavior: 'allow' } | { behavior: 'deny'; message: string }>;

export function buildCanUseTool(agentId: string, department: string): CanUseToolFn {
  const isTamir = agentId === 'tamir';
  const isDeptHead = ['cto', 'cmo', 'coo'].includes(agentId);
  const isTempEmployee = !isTamir && !isDeptHead;

  return async (toolName: string) => {
    if (!toolName.startsWith('mcp__myelin__')) {
      return { behavior: 'allow' };
    }
    if (TAMIR_ONLY.includes(toolName) && !isTamir) {
      return { behavior: 'deny', message: `Tool ${toolName} is Tamir-only` };
    }
    if (DEPT_HEAD_ONLY.includes(toolName) && !isDeptHead) {
      return { behavior: 'deny', message: `Tool ${toolName} requires department head role` };
    }
    if (isTempEmployee && !TEMP_ALLOWED.includes(toolName)) {
      return { behavior: 'deny', message: `Temp employees can only use: ${TEMP_ALLOWED.map(t => t.replace('mcp__myelin__', '')).join(', ')}` };
    }
    return { behavior: 'allow' };
  };
}
```

Note: `file_to_vault` is in DEPT_HEAD_ONLY because per TOOL-10 it's "Tamir + dept heads". Tamir passes the `!isTamir` check on TAMIR_ONLY but is also not in DEPT_HEAD_ONLY -- so add Tamir to the `file_to_vault` allowlist. Specifically, the DEPT_HEAD_ONLY check should also allow Tamir: change the check to `if (DEPT_HEAD_ONLY.includes(toolName) && !isDeptHead && !isTamir)`.

**src/lib/mcp/tools/knowledge.ts** -- Per TOOL-05 and TOOL-06:

Import `proper-lockfile` (`import * as lockfile from 'proper-lockfile'`). Import `searchDocuments` from `@/lib/fts`. Import `prisma` from `@/lib/db`. Import `generateId` from `@/lib/id`.
Define `createKnowledgeTools(ctx: ToolContext)` returning array of 3 tools:

1. `read_knowledge`: Input `{ filename: z.string().describe('Name of the knowledge file (e.g., "api-patterns.md")') }`. Reads from `data/departments/{ctx.department}/knowledge/{filename}`. Path traversal check: resolved path must startWith the knowledge directory. Returns content or error if not found.

2. `write_knowledge`: Input `{ filename: z.string(), content: z.string() }`. Path traversal check. Uses `proper-lockfile` to lock the knowledge directory during write: `await lockfile.lock(knowledgeDir, { retries: 3 })` then `writeFileSync` then `release()` in finally block. After writing, upsert to documents table via prisma: `prisma.document.upsert({ where: { id: docId }, create: { id: generateId('doc'), title: filename, content, source: 'knowledge', department: ctx.department, filedBy: ctx.agentId, filePath: fullPath }, update: { content, updatedAt: new Date() } })`. Use the file path as a lookup key -- to find existing doc, query `prisma.document.findFirst({ where: { filePath: fullPath } })` first. Returns "Knowledge file written and indexed."

3. `search_knowledge`: Input `{ query: z.string().describe('Search query (FTS5 syntax supported)'), limit: z.number().optional().describe('Max results, default 20') }`. Calls `searchDocuments(args.query, args.limit ?? 20)`. Returns formatted results: for each result, `[${result.source}] ${result.title} (${result.department})\n${result.snippet}` joined by `\n\n---\n\n`. If no results, return "No documents matched your search query." Set `annotations: { readOnlyHint: true }`.
