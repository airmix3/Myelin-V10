**src/lib/seed-agents.ts** -- Seeds 4 executives to DB:

```typescript
import { prisma } from '@/lib/db';
import { generateId } from '@/lib/id';
import { logger } from '@/lib/logger';

const EXECUTIVES = [
  { agentId: 'tamir', name: 'Tamir', department: 'global', budgetLimit: 50.0 },
  { agentId: 'cto', name: 'CTO', department: 'tech', budgetLimit: 25.0 },
  { agentId: 'cmo', name: 'CMO', department: 'marketing', budgetLimit: 25.0 },
  { agentId: 'coo', name: 'COO', department: 'operations', budgetLimit: 25.0 },
];

export async function seedAgents(): Promise<void> {
  const log = logger.child({ module: 'seed-agents' });
  for (const exec of EXECUTIVES) {
    const existing = await prisma.employee.findFirst({ where: { agentId: exec.agentId } });
    if (!existing) {
      await prisma.employee.create({
        data: {
          id: generateId('emp'),
          name: exec.name,
          role: 'executive',
          department: exec.department,
          agentId: exec.agentId,
          status: 'active',
          budgetLimit: exec.budgetLimit,
          budgetSpent: 0.0,
        },
      });
      log.info({ agentId: exec.agentId }, 'Seeded executive agent');
    } else {
      log.debug({ agentId: exec.agentId }, 'Executive agent already exists');
    }
  }
}
```

**data/departments/global/skills/memory-management/SKILL.md** -- Per D-08 and GSKILL-01:

Frontmatter:
```yaml
- - -
name: memory-management
status: active
scope: global
version: "1.0"
- - -
```

Content must include:
- **Goal:** Maintain a useful personal memory that helps you pick up context between tasks
- **When to Trigger:** Read MEMORY.md at the START of every task. Write MEMORY.md at the END of a task ONLY when something genuinely new was learned or changed. Not mandatory on every task -- use your discretion.
- **MEMORY.md Format:** Structured employee journal with 4 sections:
  1. `## Recent Projects` -- each entry: task description, deliverable path, knowledge files written. A future you should be able to pick up context from this section.
  2. `## Company Conventions` -- patterns and decisions discovered (e.g., "CEO prefers sources cited", "CTO favors async patterns")
  3. `## Goals` -- active company objectives relevant to your department
  4. `## Notes` -- anything else worth remembering
- **Reading Procedure:** Call `read_memory` tool. If empty, this is your first task -- no context to load, proceed fresh.
- **Writing Procedure:** At task end, if you learned something new: call `read_memory` to get current state, update the relevant section(s), call `write_memory` with the full updated content. Don't rewrite the whole file -- preserve existing entries and append/update.
- **Edge Cases:** If MEMORY.md is corrupted or nonsensical, start fresh. If you're unsure whether something is worth remembering, err on the side of recording it -- you can always clean up later.

**data/departments/global/skills/skill-extractor/SKILL.md** -- Per D-09 and GSKILL-02:

Frontmatter:
```yaml
- - -
name: skill-extractor
status: active
scope: global
version: "1.0"
- - -
```

Content must include:
- **Goal:** Capture reusable patterns from completed work so future agents can benefit
- **When to Trigger (Executor):** During task execution, when you notice a reusable pattern mid-work. Don't wait until the end -- capture while the context is fresh.
- **When to Trigger (Supervisor):** After approving a deliverable, do a dedicated extraction pass. Look for patterns the executor might have missed.
- **What Counts as Worth Extracting:**
  - Novel tool combination that solved a problem elegantly
  - Reusable workflow that would save time on similar future tasks
  - Domain insight that would help future agents in this department
  - API integration pattern with specific endpoints/auth/error handling
  - Content template that produced good results
- **What Does NOT Count:**
  - One-off task-specific logic
  - Standard library usage documented elsewhere
  - Personal preferences or style choices
- **Extraction Procedure:**
  1. Identify the pattern -- what would you teach a new hire about this?
  2. Name it descriptively (e.g., "eeg-data-preprocessing", "social-media-thread-format")
  3. Call `propose_skill` with: name, description (one sentence), and the full SKILL.md content
  4. SKILL.md content should follow the standard format: goal, when to trigger, step-by-step procedure, edge cases
- **Approval Chain:** Proposed skills go through: dept head review -> CEO approval -> active

**data/departments/global/skills/system-reset/SKILL.md** -- Per D-10 and GSKILL-03:

Frontmatter:
```yaml
- - -
name: system-reset
status: active
scope: global
version: "1.0"
- - -
```

Content must include:
- **Goal:** Safely reset the system to a clean state while preserving permanent assets
- **When to Trigger:** Only when the CEO explicitly requests a system reset through Tamir. This is an admin operation, not a task -- do not route to departments.
- **Procedure (Tamir handles this directly):**
  1. CEO requests reset
  2. Ask CEO what to preserve beyond defaults (options: in-progress deliverables? skill proposals? cost history?)
  3. Generate and display a summary: "Will delete: X tasks, Y deliverables, Z cost events, N activity log entries. Will preserve: vault docs, company DNA, approved skills, permanent employees, [CEO's choices]"
  4. Wait for explicit CEO confirmation ("confirm reset" or similar)
  5. Execute reset (this is a technical operation -- the steps below):
     - Delete all rows from: task_runs, cost_events, activity_log, hire_requests
     - Delete tasks and their deliverables (unless CEO chose to preserve in-progress)
     - Delete non-vault documents (source != 'vault')
     - Reset employee budgetSpent to 0.0 for all permanent employees
     - Terminate all temp employees (set status = 'terminated')
     - Preserve: vault documents, company DNA, approved/active skills, permanent employees
     - Optionally preserve items CEO requested
  6. Confirm completion: "Reset complete. System is clean. [summary of what was preserved]"
- **Safety:** One confirmation gate (the summary). Not instant, not overly paranoid. If CEO says "reset" without seeing the summary, show the summary first.
- **Edge Cases:** If reset fails partway, report what was deleted and what wasn't. Don't silently fail.
