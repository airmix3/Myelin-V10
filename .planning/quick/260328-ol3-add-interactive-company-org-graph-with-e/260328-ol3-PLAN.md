    **3. Create `src/app/api/terminal/[runId]/route.ts`** -- SSE+POST terminal endpoint:
    - Since Next.js 14 API routes don't natively support WebSocket upgrade, use **two HTTP methods**:
      - `GET /api/terminal/[runId]` -- SSE stream that forwards PTY output to the client (same pattern as existing SSE)
      - `POST /api/terminal/[runId]` -- Receives keyboard input from client, writes to PTY via pty-manager
      - `DELETE /api/terminal/[runId]` -- Force-kills terminal and resumes SDK agent
    - GET handler: Validates runId exists in task_runs, checks sessionId is present. Calls pauseRun() then spawnTerminal() if not already active. Returns SSE stream: each PTY data chunk sent as `event: data\ndata: {base64 encoded chunk}\n\n`. On PTY exit, send `event: exit\ndata: {}\n\n`, call resumeRun(), and close stream.
    - POST handler: Accepts JSON body `{ type: 'input' | 'resize', data?: string, cols?: number, rows?: number }`. For 'input': base64 decode data, call writeToTerminal(). For 'resize': call resizeTerminal().
    - DELETE handler: calls killTerminal() + resumeRun(). Returns 200.

    **4. Modify `src/lib/worker.ts`** -- Add pause/resume support:
    - Add a module-level `const pausedRuns = new Set<string>()`
    - Add exported `pauseRun(runId: string): Promise<void>`:
      - Add runId to pausedRuns set
      - Call `abortQuery(runId)` from invoke-agent.ts to stop the SDK loop gracefully
      - The SDK will save its session state -- the sessionId persists
      - Update task_runs status to 'paused' in DB
      - Emit eventBus 'worker:pause' event
    - Add exported `resumeRun(runId: string): Promise<void>`:
      - Remove from pausedRuns set
      - Update task_runs status to 'queued' in DB (so worker picks it up again)
      - The worker's poll() will find it and call executeRun() which uses the stored sessionId to resume
      - Emit eventBus 'worker:resume' event
    - In `claimNextRun()`: skip runs in pausedRuns set

    **5. Export query abort from invoke-agent.ts:**
    - Add: `export function abortQuery(runId: string): void { const q = queryRegistry.get(runId); if (q) { q.abort(); queryRegistry.delete(runId); } }`

    **6. Create `src/app/org-graph/TerminalOverlay.tsx`** -- xterm.js terminal component:
    - Import `Terminal` from '@xterm/xterm' and `FitAddon` from '@xterm/addon-fit' dynamically (next/dynamic with ssr: false since xterm needs DOM)
    - Props: `{ runId: string, onClose: () => void }`
    - On mount:
      - Create Terminal instance with theme matching cortex.css (background: #0a0a0f, foreground: #e0e0e8)
      - Load FitAddon, call fit()
      - Open EventSource to `/api/terminal/${runId}` for PTY output
      - On 'data' event: base64 decode, terminal.write()
      - On 'exit' event: show "Session ended" message, call onClose() after 2s
      - terminal.onData (keyboard input): POST to `/api/terminal/${runId}` with `{ type: 'input', data: btoa(input) }`
      - terminal.onResize: POST with `{ type: 'resize', cols, rows }`
    - Render: Full-screen overlay (position fixed, z-index 200, background rgba(0,0,0,0.9))
      - Top bar: "Taking over [agent name] - Session [runId]" + "Exit Role" button (red)
      - Terminal div ref fills remaining space
      - "Exit Role" button: POST `{ type: 'input', data: btoa('/exit\n') }` to gracefully exit claude, then wait for 'exit' SSE event. If no exit after 5s, call DELETE /api/terminal/[runId] to force-kill.
    - Import xterm CSS: `import '@xterm/xterm/css/xterm.css'` -- add `@xterm/xterm` to next.config.mjs transpilePackages if CSS import fails.
