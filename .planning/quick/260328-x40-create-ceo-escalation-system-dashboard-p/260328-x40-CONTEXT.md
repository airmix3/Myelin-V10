# Quick Task 260328-x40: CEO Escalation System - Context

**Gathered:** 2026-03-28
**Status:** Ready for planning

<domain>
## Task Boundary

Create the CEO escalation system - dashboard escalations preview (top of left panel), dedicated Escalations navbar tab with card-based UI, approve/decline/free-text interactions, agent tree integration (show escalations when clicking an agent), and MCP escalate tool for employees and dept heads. Escalations route through Tamir (CoS) for triage before reaching CEO.

</domain>

<decisions>
## Implementation Decisions

### Escalation Types & Scope
- Support the 3 docs-defined types (clarification, hire_approval, budget_increase) PLUS a generic "custom" type for anything else agents want to surface
- Routing: Tamir triages all escalations — agents set input-required, Tamir decides if CEO needs to see it. This adds a triage layer before CEO dashboard.

### Dashboard Layout
- Escalations preview appears at TOP of left panel — CEO sees action items first
- Full Escalations tab uses card list layout: each escalation as a card with context, agent info, type badge, and action buttons
- Approve/Decline buttons for approval-type escalations
- Free text input + Send button for clarification-type escalations

### MCP Tool Design
- Single `escalate_to_ceo` tool with `type` param (clarification/hire_approval/budget_increase/custom) + structured context object
- Both employees and dept heads use the same tool
- Agent provides: summary, reason, taskId, agentId, urgency, plus type-specific optional fields (cost estimate, candidate role, question text, etc.)
- System auto-enriches from DB: task details, recent activity, budget status — so CEO always has full picture even if agent provides minimal context

### Claude's Discretion
- DB schema for escalations table (fields, indexes)
- API endpoint structure for escalation CRUD and actions
- How Tamir triage logic works (auto-forward vs hold)
- Color coding and urgency indicators in UI

</decisions>
